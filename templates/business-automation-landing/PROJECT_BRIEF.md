# Project Brief — Business Automation Landing

## Vision
Create a premium, modern, interactive landing page for a company offering automation of business operations. The interface should feel like a **living but understandable digital system**. Explain practical benefits through systems that visibly work, not decorative animation unrelated to the copy.

## Positioning and messaging
- Audience: owners, managers, operations leaders and technical decision-makers who want to reduce manual work and connect systems.
- Core proposition: connect fragmented tools, streamline processes, move data reliably, provide visibility and build custom digital workflows.
- Voice: precise, approachable, technically competent; no empty hype or unsupported numerical ROI promises.
- Conversion: clear invitation to discuss a process or request an automation assessment; define the exact CTA and lead-capture method when implementation begins.

## Design direction
- Restrained premium technology aesthetic; clean grids, bold whitespace, carefully controlled color and measured animation.
- The choice of light/dark mode, accent colors, visual symbols and section lengths should follow the actual brand assets and content when available.
- Typography: standard genuine Medeo for most readable text; a genuine pixelated/digital Medeo variant **only if supplied** for sparse IT emphasis. Do not invent font weight names or a pixelated Medeo file. Validate Cyrillic and rights, and make typography robust to missing assets.
- Mobile-first readability, tactile feedback, reduced-motion and accessible contrast.

## Suggested narrative sections (validate against final service offer)
1. **Hero: automation turns scattered tasks into a coherent system.** Graphical motif: disconnected events becoming an organized flow. Short statement + primary CTA.
2. **Problems and outcomes: manual handoffs, copy-paste, lost visibility.** Show before → after state without claiming exact savings.
3. **How automations work: trigger → rules → actions → result.** Interactive connected diagram with scroll revealing each logical step.
4. **Integrations and APIs: systems exchanging data.** Distinct application nodes, request arrows, acknowledgement and synchronization.
5. **Backend and databases: information moves through infrastructure.** Client → API → backend services → DB → response. Distinguish query, write/read and return path. Do not imply that every architecture uses the same topology.
6. **Analytics and monitoring: see what is happening.** Sample events that roll up into a labeled demonstration dashboard.
7. **AI-assisted workflows (only if genuinely offered):** validation and meaningful human checkpoints, not magical AI claims.
8. **Capabilities / process / FAQ / final CTA.** Address engagement process, scope, reliability, maintenance and next contact.

## Content-first graphics
For each section specify: customer-facing explanation; exact entities; actual flow; scroll checkpoints; interactive affordance; static or reduced-motion version; mobile condensation; accessibility labels. Avoid fake live backend calls, fabricated logos, unlicensed imagery, unexplained graphs or impossible architecture.

## Technical starting point
Inspect the actual chosen project's framework; React + GSAP ScrollTrigger are options, not mandatory. Use SVG for labeled networks and path animation first; consider Canvas/WebGL only for demonstrated complexity or performance needs. Build a functional non-animated page before cinematic effects.

## Inputs to confirm during implementation (do not invent)
Real brand/company name, list of actual services, proof/cases/metrics, CTA destination, contact/legal data, logo/colors, licensed Medeo variants/fonts, screenshots/visual assets and hosting/deployment constraints.

## Definition of done
Accurate service copy, usable CTAs, desktop/mobile UX, purposeful scroll interactions, reduced-motion alternatives, meaningful graphics, build/lint results and transparent reporting on unverified behavior.
